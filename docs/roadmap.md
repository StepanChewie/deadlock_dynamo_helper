## 2. Главный вывод дня: мониторинг смотрел не туда

Контейнер был нетрудоспособен **30 часов**, и никто не заметил. Разбор:

- **Uptime Kuma смотрел на HTTP-эндпоинт** и всё это время получал `200` — потому что Node однопроцессный и событийный: он обслуживает запросы, **не форкая процессы**. Сервис был «зелёным».
- **Docker healthcheck форкает `node -e`** — и падал 1843 раза подряд. Красный статус был виден только в `docker inspect`.

То есть отказ был **невидим для существующего мониторинга по построению**. Это не «добавить алерт», это выбор правильного сигнала: HTTP-код здесь не является признаком здоровья. Единственный сигнал, который поймал бы это сразу, — счётчик задач cgroup.

## 6. Решения (приняты 2026-09-16)

1. **Удалять `deadlock-live-events-1`** — да, удалён.
2. **Ротация `DEADLOCK_API_KEY`** — делает владелец сам, в удобный момент. До этого ключ считается скомпрометированным.
3. **DuckDNS остаётся production-хостом** — другого домена пока нет. **Следствие для PR 10:** проверять «сборка получила явный `OVERWOLF_API_BASE_URL`», а **не** «origin не duckdns». Это разные утверждения, и второе сломает легитимную сборку.
4. **Сколько тегов образов держать** — `current` + 3–4 последних по коммиту. Этого хватает для отката, и любой из них воспроизводим из своего коммита.
5. **Общий build cache** — чистить, сделано. Цена принята: первый деплой любого из трёх проектов будет медленнее, пока кеш не прогреется.

Открытых решений, блокирующих фазы, не осталось. Ближайший шаг — **S1**.
