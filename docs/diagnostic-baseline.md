# Diagnostic match parser and baseline

This research pipeline reads ZIP archives exported by the Overwolf Diagnostic Capture panel. It does not replace the production historical build graph. Its purpose is to validate live inventory semantics, produce canonical examples from captured matches, and measure a simple next-action baseline without leaking the held-out match into training.

## Input

Each archive must be an unmodified Diagnostic Capture ZIP containing:

- `overwolf-events.ndjson`
- `session-info.json`
- `notes.json`

The parser supports the stored ZIP format generated by the client. Compressed ZIP entries and data descriptors are rejected deliberately so corrupted or externally repacked archives are not silently accepted.

## Parsed state

The parser reconstructs:

- match IDs and wall-clock ordering
- roster and local-player identity
- game clock
- per-player inventory snapshots
- canonical inventory actions
- team score
- incoming damage grouped by source
- manual marker matches

Inventory normalization reuses `@dynamo-lab/build-domain`:

- the first snapshot is `RECONCILE`
- new items become `BUY` or `REBUY`
- recipe component replacement becomes `UPGRADE`
- a local-player removal becomes `SELL` or `CONSUME` only when a matching manual marker exists
- an unexplained removal remains `UNKNOWN_REMOVE`

Manual markers never fabricate an action. A marker is only confirmation for a telemetry-derived inventory transition. Incorrect markers remain `UNMATCHED` diagnostics.

## Training examples

Only `BUY`, `REBUY`, `UPGRADE`, and confirmed `SELL` actions become training examples. Each example contains:

- hero and team
- enemy hero roster
- game time and Early/Mid/Late phase
- canonical inventory state before and after the action
- next action and item
- latest team score
- latest local incoming-damage snapshot
- marker-confirmation status

## Baseline model

The baseline ranks empirical next-action frequencies with this backoff order:

1. hero + phase + exact inventory state
2. hero + phase
3. hero
4. global

The model filters obviously illegal actions against the current inventory. It is intentionally simple and acts as a lower bound for the production graph recommender.

Evaluation uses leave-one-match-out validation. Every match is predicted using a model trained only on the other matches.

## CLI

Build the domain package:

```bash
yarn workspace @dynamo-lab/build-domain build
```

Generate a report:

```bash
yarn workspace @dynamo-lab/build-domain diagnostics:baseline -- \
  /path/to/match-a.zip \
  /path/to/match-b.zip \
  --recipes /path/to/recipes.json \
  --output diagnostic-baseline-report.json
```

Recipe JSON format:

```json
[
  {
    "parentItemId": 2064029594,
    "componentItemIds": [3077079169]
  }
]
```

The report includes parser diagnostics, marker matches, dataset counts, model coverage, leave-one-match-out top-1/top-3 accuracy, and recommendations for the latest local-player state in each archive.
